# 페이지 1/2 — 서비스 정의와 사용자 경험

## 1. 권장 주제명

### 지역박물관 맞춤 방문 플래너 & AI 문화유산 여행 도슨트

## 2. 한 문장 정의

> 지방 국립박물관을 처음 방문하는 일반 여행자의 방문시간·관심 주제·이동조건을 바탕으로 실행 가능한 관람계획을 만들고, 현장에서 선택한 유물에 대해 공식 자료와 출처에 근거한 맞춤 해설과 후속 질문을 제공하는 RAG 기반 여행 도슨트

## 3. 결합 방향에 대한 판단

두 아이디어는 다음처럼 **방문 전과 방문 중**을 연결할 때 자연스럽게 결합됩니다.

```text
방문 전
방문일·체류시간·관심사 입력
        ↓
운영 여부·기본 교통·주차 확인
        ↓
시간 안에 가능한 관람 주제와 유물 순서 추천
        ↓
외부 지도 서비스로 실제 이동

방문 중
장소·유물 선택 또는 QR 입력
        ↓
관심사와 설명 수준에 맞춘 AI 도슨트
        ↓
자유 질문 → 출처 제시 → 근거 부족 시 답변 보류
        ↓
선택형 퀴즈·관람 기록·다음 유물 추천
```

결합의 핵심은 기능을 많이 넣는 것이 아니라, **추천한 관람계획과 현장 도슨트가 같은 유물·공식 자료·사용자 조건을 공유하는 것**입니다. 방문계획만 제공하면 일반 일정 앱에 가까워지고, 해설만 제공하면 일반 문화유산 챗봇에 가까워집니다. 두 기능이 연결되어야 사용자에게 “왜 이 유물을 지금 봐야 하는지”까지 설명할 수 있습니다.

## 4. 해결하려는 문제

일반 여행자는 박물관 방문 전후에 다음 정보를 따로 찾아야 합니다.

- 방문일의 휴관 여부, 운영시간과 입장 마감
- 주차장 또는 대중교통과 실제 길찾기
- 제한된 시간에 볼 만한 전시와 대표 유물
- 유물별로 길고 어려운 공식 설명을 이해하기 쉬운 해설
- 관람 중 생긴 질문에 대한 신뢰할 수 있는 답변

범용 생성형 AI는 질문에 답하거나 일반적인 일정을 제안할 수 있지만, 대상 박물관의 실제 소장품·운영정보·관람시간 제약을 한 흐름에서 검증하고 출처와 기준일을 일관되게 보여준다고 보장할 수는 없습니다.

## 5. 핵심 사용자와 B2B/B2C 구조

### MVP 핵심 사용자 — B2C

> **지방 국립박물관을 처음 방문하며 1~3시간 안에 무엇을 볼지 정하고 싶은 일반 여행자**

직업이나 세부 나이를 필수로 받지 않고, 서비스 결과에 실제로 영향을 주는 조건만 입력받습니다.

- 관심 주제: 왕실·생활·전쟁·종교·미술 등
- 설명 수준: 쉬운 설명 / 일반 설명 / 심화 설명
- 관람 깊이: 60분 핵심 / 120분 여유
- 이동수단: 자동차 / 대중교통
- 선택 조건: 유아·노약자 동반, 도보 최소화 등

### 확장 가능한 B2B 고객

- 지방 국립박물관 및 공립박물관
- 지역관광재단·지방자치단체 관광부서
- 여행·관광 플랫폼

B2B는 MVP의 관리자 화면을 크게 만드는 이유가 아니라, 향후 다음 가치를 설명하기 위한 확장 구조입니다.

- 소장품과 지역 관광정보의 노출 확대
- 관람객 관심사와 질문 유형의 익명 통계
- 다국어·무장애 해설 확장
- 지역 내 체류시간과 주변 방문 연계

## 6. 핵심 기능과 우선순위

| 구분 | 기능 | MVP 포함 | 판단 |
|---|---|:---:|---|
| 방문 가능성 | 휴관일·운영시간·입장 마감 확인 | 포함 | 잘못된 계획을 먼저 차단 |
| 기본 이동정보 | 주차장·주요 정류장·외부 길찾기 연결 | 포함 | 자체 경로 계산은 하지 않음 |
| 맞춤 관람계획 | 관심사와 60·120분 조건에 맞춘 유물 순서 | 포함 | 결합 서비스의 중심 |
| AI 도슨트 | 공식 자료 기반 수준별 유물 해설 | 포함 | RAG 핵심 기능 |
| 자유 질문 | 근거 검색·출처 표시·답변 보류 | 포함 | 환각 방지 검증 대상 |
| 현장 선택 | 유물명 검색 또는 미리 등록한 QR 코드 | 포함 | 위치추적 없이도 시연 가능 |
| 퀴즈·스탬프 | 관람한 유물 기반 간단한 퀴즈·기록 | 선택 | 핵심 기능 완성 후 추가 |
| 다국어 | 영어 등 외국어 해설 | 확장 | 번역 평가 부담으로 MVP 제외 권장 |
| 실시간 주차 | 현재 잔여 주차면 제공 | 제외 | 공식 API가 실제 제공되는 경우에만 확장 |
| 실내 내비게이션 | 현재 위치 기반 관내 길찾기 | 제외 | 도면·비콘·좌표 데이터 필요 |

## 7. 범용 Gemini·ChatGPT와 구분하려면

“문화유산에 대해 대화할 수 있다”만으로는 차별성이 약합니다. 아래 요소를 실제로 구현해야 프로젝트 고유성이 생깁니다.

| 범용 AI에 질문 | 권장 프로젝트 |
|---|---|
| 사용자가 필요한 정보를 직접 설명 | 박물관·방문일·시간·관심사 입력 구조화 |
| 최신 운영정보와 소장 여부가 불확실할 수 있음 | 지정 기관의 공식 자료와 기준일 관리 |
| 답변과 실제 관람 순서가 분리됨 | 추천 유물 순서와 도슨트 대화 상태 연결 |
| 출처가 누락되거나 포괄적일 수 있음 | 문장별 또는 답변별 근거·원문 링크 제공 |
| 시간·휴관 조건 위반을 체계적으로 검사하지 않음 | 프로그램 규칙으로 일정 제약 검사 |
| 어떤 질문에 답하지 말아야 하는지 불명확 | 근거 점수 미달 시 재검색 또는 답변 보류 |

> **차별화 판단 기준:** 발표에서 “같은 질문을 범용 LLM에 입력한 결과”와 “공식 RAG·시간 제약 검사를 거친 결과”를 비교할 수 있어야 합니다.

# 페이지 2/2 — 데이터·구현·제한요소와 MVP

## 8. 데이터 구성과 수집 방법

모든 데이터를 벡터DB에 넣지 않고 성격에 따라 분리합니다.

| 데이터 계층 | 예시 | 저장·처리 방법 | 수집 후보 |
|---|---|---|---|
| 문화유산 문서 | 유물 해설, 전시 설명, 관련 역사 | 원문 보존 → 청크 → 임베딩 → 벡터DB | e뮤지엄, 대상 박물관 공식 자료 |
| 유물 메타데이터 | 시대·재질·분류·전시관·교육 태그 | 관계형 DB 또는 메타데이터 필터 | e뮤지엄·박물관 소장품 정보 |
| 시설 운영정보 | 운영시간·휴관일·요금·편의시설 | 관계형 DB·규칙 검사 | 박물관 공식 홈페이지 |
| 교통·주차 | 위치·운영시간·요금·정류장 | 관계형·공간 데이터, 필요 시 API | 공공데이터포털·지자체 자료 |
| 사용자 세션 | 관심사·설명 수준·관람시간·선택 유물 | 세션 저장 후 최소 보관 | 서비스 입력 |
| 평가 정답셋 | 질문·정답 근거·관련 유물·답변 가능 여부 | 별도 평가 데이터셋 | 팀 수작업 검수 |

### 권장 수집 순서

1. 지방 국립박물관 **1곳**을 정합니다.
2. 상설전시실 **1개 또는 하나의 연결 주제**를 정합니다.
3. 대표 유물 **30~50점**의 설명·메타데이터·출처 URL을 수집합니다.
4. 운영시간·휴관일·주차장·주요 정류장을 별도 표로 작성합니다.
5. `시대 / 유형 / 재료 / 주제 / 난도 / 예상 관람시간` 태그를 정규화합니다.
6. 사실 질문·비교 질문·추천 질문·답변 불가 질문으로 평가셋을 만듭니다.
7. 원본과 전처리본을 분리하고 수집일·기준일·이용조건을 저장합니다.

공식 데이터 후보:

- [e뮤지엄](https://emuseum.go.kr/): 전국 박물관 소장품 통합검색과 Open API 안내
- [전국주차장정보 표준데이터](https://www.data.go.kr/data/15012896/openapi.do): 위치·운영시간·요금 등 정형정보 후보
- 대상 박물관 공식 홈페이지: 운영시간·휴관·관람안내의 최우선 출처

## 9. 권장 시스템 구조

```text
사용자 조건
박물관·방문일·관람시간·관심사·설명 수준
                         ↓
                 LangGraph 상태 관리
       ┌─────────────────┼─────────────────┐
  운영·시간 규칙      문화유산 Hybrid RAG      교통·주차 DB
  휴관·마감 검사      키워드+벡터+필터 검색     위치·요금·정류장
       └─────────────────┼─────────────────┘
                         ↓
              관람 후보 선정·시간 제약 검사
                         ↓
         관람 순서 + 근거 + 외부 지도 연결 제공
                         ↓
          현장 유물 선택 → 맞춤 해설 → 자유 질문
                         ↓
        근거 일치 검사 → 재검색 / 답변 / 답변 보류
```

- **LangChain:** 문서 적재, 검색기, 프롬프트와 출력 파서 구성
- **Vector DB·Hybrid RAG:** 유물·전시 설명 검색과 메타데이터 필터
- **LangGraph:** 방문 조건 확인 → 검색 → 계획 검사 → 도슨트 → 재검색·보류 분기
- **일반 코드·정형 DB:** 운영시간, 소요시간, 요금과 조건 계산
- **프롬프트:** 설명 수준, 출처 표시, 추측 금지와 답변 형식 통제
- **Fine-tuning:** 시작부터 필수화하지 않고 기본 LLM → RAG → RAG+검증 비교 후 결정

## 10. 권장 MVP

> **지방 국립박물관 한 곳의 대표 유물 30~50점을 대상으로, 60분·120분 맞춤 관람계획과 공식 출처 기반 현장 도슨트 대화를 제공하는 웹 서비스**

| 항목 | 권장 범위 |
|---|---|
| 기관 | 지방 국립박물관 1곳 |
| 전시 범위 | 상설전시실 1개 또는 연결 주제 1개 |
| 유물 | 30~50점 |
| 핵심 사용자 | 처음 방문하는 일반 여행자 |
| 관람 모드 | 60분 핵심 / 120분 여유 |
| 설명 수준 | 쉬운 / 일반 / 심화 |
| 이동정보 | 운영 여부, 기본 주차·정류장, 외부 지도 연결 |
| 현장 입력 | 유물명 선택 또는 사전 등록 QR |
| AI 기능 | 관람 추천, 근거 기반 해설, 자유 질문, 답변 보류 |
| 제외 | 자체 길찾기, 전국 서비스, 실시간 주차 보장, 실내 위치추적 |

## 11. 주요 제한요소와 개선안

| 제한요소 | 위험 | 개선·권장안 |
|---|---|---|
| 기능 과다 | 교통·지도 구현이 도슨트 RAG를 압도 | 교통은 기본정보와 외부 지도 연결로 제한 |
| 최신성 혼합 | 오래된 운영정보를 현재 사실처럼 안내 | 기준일·마지막 확인일·실시간 여부 표시 |
| 관람시간 추정 | 실제 이동·혼잡과 차이 | 고정된 예상 소요시간과 여유시간 적용, 보장 표현 금지 |
| 잘못된 역사 해설 | 신뢰도 저하 | 공식 자료 우선, 출처 표시, 근거 미달 시 보류 |
| 위치 기반 개인정보 | 불필요한 위치 저장 | 정확한 위치 대신 출발 지역 선택 허용, 세션 최소화 |
| 범용 LLM과 유사 | 단순 챗봇으로 보일 수 있음 | 계획 상태와 현장 대화를 연결하고 비교평가 실시 |
| Fine-tuning 과잉 | 데이터 부족 상태에서 성능 설명이 어려움 | 표현 일관성 문제를 측정한 뒤 소규모 비교실험 |

## 12. 테스트 및 평가 기준

- 검색 적합성: 정답 근거가 Top-K에 포함되는 비율
- 사실 충실성: 답변 문장이 검색 근거와 일치하는 비율
- 출처 표시율: 사실 답변에 공식 출처가 포함된 비율
- 답변 보류율: 근거 없는 질문에서 추측하지 않은 비율
- 일정 유효성: 휴관·마감·총시간 조건 위반 건수
- 추천 타당성: 관심 주제와 추천 유물 태그의 일치율
- 연결성: 추천한 유물이 현장 도슨트 화면에서 그대로 이어지는 비율
- 비교 실험: 기본 LLM / RAG / RAG+검증의 정확도·환각률·응답시간 비교

### 팀 공유용 핵심 요약

> 방문 도우미와 문화유산 도슨트는 결합 가능하지만, 전국 여행·자체 내비게이션까지 확장하면 범위가 과도합니다. 지방 국립박물관 1곳, 유물 30~50점, 60·120분 관람 모드로 제한하고 `방문 조건 확인 → 관람 순서 추천 → 현장 유물 해설 → 자유 질문과 출처`를 하나의 흐름으로 구현하는 것이 권장됩니다. 범용 LLM과의 차이는 공식 기관 데이터, 시간 제약 검사, 계획과 현장 대화의 연결, 근거 부족 시 답변 보류를 실제로 구현하고 비교평가할 때 확보됩니다.
