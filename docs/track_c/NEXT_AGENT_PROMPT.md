# 다음 개발자/AI에게 전달할 프롬프트

아래 내용을 복사해서 사용한다. 새 구현을 원하면 첫 문장의 ‘이어받아’를 ‘같은 요구사항으로 재구현해’로 바꿀 수 있다. 인계 문서도 함께 제공한다.

---

한국 문화유산 맞춤형 답변 서비스의 Track C Streamlit 작업을 이어받아 주세요. 이전 대화 내용을 알고 있다고 가정하지 말고, 먼저 `docs/track_c/STREAMLIT_HANDOFF.md`와 현재 코드를 읽고 작업하세요. 이 인계 문서는 API의 최종 확정 계약이 아니므로 최신 팀 계약과 실제 RAG 응답도 확인해야 합니다.

저장소는 SKN33-3rd-1Team입니다. 작업 브랜치는 `feature/track-c-streamlit-mock`이었습니다. 현재 체크아웃한 저장소 루트에서 작업하세요. 브랜치와 변경 파일을 먼저 확인하고 다른 사람의 변경을 보존하세요.

현재 앱은 실제 검색·생성·평가가 연결되지 않은 Mock UI입니다. 임의의 질문을 해도 선택한 유형의 예시 답변이 나옵니다. 코드가 있다고 실기능이 완료됐다고 말하지 마세요.

필수 요구사항은 다음과 같습니다.

1. 기본 실행 파일과 탭별 모듈을 분리합니다. 현재는 질문하기, 답변 과정, 평가 결과, 문화유산 탐험 지도의 네 탭입니다. 서비스 안내 탭은 제거한 상태입니다.
2. 첫 탭에서 제출한 질문·설명 수준·검색 문맥·사용 청크 ID·최종 답변·출처가 하나의 요청으로 다른 탭까지 이어져야 합니다. 현재는 st.session_state의 last_result를 사용합니다. 요청 ID와 평가 상태도 일치시켜 주세요. 새 질문에 이전 평가가 붙으면 안 됩니다.
3. 맞춤형 답변이 핵심입니다. 어린이·청소년·일반·전문가 등을 고려하되 UI 이름과 API 값을 임의로 확정하지 마세요. 기존 문서에는 audience_level=easy/general/advanced가 있습니다. UI는 선택과 전달을 맡고 실제 설명 수준 변경은 생성/RAG 코드가 처리해야 합니다.
4. 답변 과정은 일반적인 절차 소개가 아닙니다. 방금 질문에서 실제로 검색된 청크, 검색 점수의 의미, 사용된 근거, 최종 출력 답변을 보여 주세요. 비밀 프롬프트나 숨은 사고과정을 노출하지 마세요.
5. 평가 결과는 수업의 04_ragas.ipynb와 03_llm_as_a_judge_hf_cookbook.ipynb 아이디어를 참고합니다. 질문·문맥·최종 답변·필요한 기준 답·실제 지표·판정 이유를 연결해 주세요. 지금의 0.92/0.89/0.86/0.90 및 심사 의견은 전부 고정 예시입니다. 이를 실측처럼 표시하면 안 됩니다. 별도 LLM 심사 의견을 RAGAS 숫자의 정확한 산출 이유라고 단정하지 마세요. 실제 평가가 없으면 평가 전으로 표시하세요.
6. 탐험 지도는 반드시 노드를 직접 누르면 그 위치에서 가지가 펼쳐져야 합니다. 초기에는 파란 길쌈노래만 표시하고, 이를 클릭하면 민요·노동요·길쌈이 선으로 연결되어 나타납니다. 민요를 클릭하면 아리랑·강강술래·정선아리랑으로 확장됩니다. 재클릭하면 접힙니다. 아래에 따로 카드 목록을 나열하는 UI로 바꾸지 마세요.
7. 마지막 가지를 클릭하면 지도 안에 한 줄 설명이 나타나고 다른 항목 클릭 시 내용이 바뀌어야 합니다. 닫기와 초기화도 유지하세요. 현재 HTML/JS에는 이 동작이 구현되어 있고 데이터는 Mock입니다. 실제 검색 결과가 없으면 설명·관계를 꾸며내지 마세요.
8. 노드 클릭 때 실제 관련 검색을 하려면 브라우저 클릭과 Python/서버 사이 연결이 추가로 필요합니다. 현재 지도는 미리 받은 Mock 자료를 펼칠 뿐 Pinecone을 재검색하지 않습니다. 연관 키워드·검색 근거·관련 문서·요약을 분리하고 확정되지 않은 related_keywords 필드를 팀 공통 계약처럼 취급하지 마세요.
9. 출처 근거는 같은 요청의 RetrievedContext와 used_chunk_ids에서 연결합니다. 근거 표시를 위해 Pinecone을 재조회하지 마세요. 탐험 지도에서 새로운 키워드로 관련 자료를 검색하는 것은 별도 기능입니다.
10. citations의 source, source_url, url은 현재 문서·UI 사이 차이가 있습니다. 최신 계약을 확인해 어댑터에서 통일하세요. 기관명과 URL을 섞지 마세요. 현재 Mock에는 제목과 URL이 맞지 않는 예시도 있으므로 실데이터처럼 재사용하지 마세요.

주요 파일:

- app/app.py: 실행과 탭 배치
- app/tabs/chat.py: 질문·세션 공유
- app/tabs/process.py: 실제 요청 추적 화면 틀
- app/tabs/evaluation.py: 고정 점수·설명·심사 의견
- app/tabs/explore.py: 지도 데이터와 Mock 관계·요약
- app/components/exploration_map.html: 노드 클릭 확장·접기·설명창
- app/components/response_cards.py: 유형별 화면과 브라우저 TTS
- app/components/citations.py: 출처·근거 표시
- app/mock_responses.py: 임시 응답 형식
- docs/track_b/02_generation_contract.md, docs/retrieved_context_contract.md: 현재 체크아웃의 계약
- src/rag_indexing/pinecone_store.py: 기존 검색 반환 코드

기존 동작을 확인한 뒤, 추가 지시가 없다면 화면의 Mock 표시 및 필드 불일치 등 확실한 개선부터 진행하세요. 실제 API 예시나 접근 권한이 없으면 연결 경계를 정리하고 해당 기능은 명확히 미연결로 남기세요. UI 코드 개선과 Mock 시연은 계속할 수 있습니다. 검색·생성·평가 API가 탭을 클릭할 때마다 중복 호출되지 않게 하세요.

현재 컴포넌트는 브라우저 SpeechSynthesis와 iframe을 사용합니다. 음성 재생 정책과 HTML 컴포넌트 버전 경고를 확인하세요. 지도 문자열은 안전하게 전달하고 외부 텍스트를 실행 가능한 HTML/JS로 넣지 마세요.

검증은 실제 화면에서 수행해 주세요: 질문 제출과 탭별 결과 일치, 길쌈노래→민요 확장, 마지막 노드의 한 줄 설명, 다른 설명으로 전환, 닫기, 가지 접기, 초기화. Python 문법 검사만으로 클릭 동작 검증을 대신하지 마세요.

API 키·.env·큰 데이터 파일은 커밋하지 마세요. 기존 Pinecone 인덱스 삭제·전체 재적재·재임베딩·유료 플랜 변경은 이 작업에 포함되지 않습니다. 별도 요청 없이 PR 제출·머지하거나 팀원에게 메시지를 보내지 마세요.
