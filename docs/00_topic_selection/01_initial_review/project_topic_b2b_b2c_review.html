1. 세 아이디어 종합 평가

1.1. 먼저 결론

세 방향 중 교육과정 적합성, 데이터 신뢰성, B2B/B2C 확장성, 완성 가능성을 함께 고려하면 교육 프로그램을 중심으로 기존 문화유산 도슨트를 B2B2C형 서비스로 확장하는 방향이 가장 안정적입니다.

단순한 문화유산 질의응답이 아니라 다음과 같이 정의할 수 있습니다.

지역 박물관과 교사가 공식 자료를 바탕으로 교육 콘텐츠를 제작·검수하고, 학생과 관람객은 자신의 수준에 맞는 해설·문제·오답 설명을 제공받는 AI 교육 플랫폼

이 방향은 기존 문화유산 조사와 범위 설계를 재사용하면서 강사님이 제안한 실무성과 포트폴리오 설명력을 추가할 수 있습니다.

1.3. 각 주제의 핵심 판단

문화유산 굿즈 제작

  • 공식 유물 데이터는 확보할 수 있으나 업체별 재료·단가·납기·최소주문수량 데이터가 부족할 가능성이 큽니다.
  • 실제 업체와 협력하거나 생산조건을 제공받는다면 차별화된 B2B 프로젝트가 될 수 있습니다.
  • 협력 데이터가 없다면 실제 제조 추천보다 상품기획서와 디자인 브리프 생성으로 범위를 줄여야 합니다.

역사교육 프로그램

  • 박물관·국사편찬위원회·한국사능력검정시험의 공식 자료를 연결할 수 있습니다.
  • 교사·박물관 담당자는 B2B 고객, 학생·관람객은 B2C 사용자가 되는 구조가 자연스럽습니다.
  • RAG, Vector DB, LangGraph 검증, 환각 방지, 수준별 설명을 모두 교육과정과 연결하기 좋습니다.

길 안내 발전형

  • 시장성과 사용자 문제는 분명하지만 지도·GIS·실시간 데이터·추천시스템이 핵심입니다.
  • 주차, 단속, 리뷰, 그늘·우천 경로는 각각 다른 프로젝트에 가깝습니다.
  • 현재 범위를 그대로 추진하면 구현보다 외부 API와 데이터 제약에 많은 시간이 소요될 가능성이 큽니다.

2. 문화유산 굿즈 제작 관련

2.1. 주제 정의

문화유산 굿즈는 기존 AI 도슨트보다 B2B 고객을 명확하게 설정할 수 있다는 장점이 있습니다.

잠재 고객

  • 지방 박물관 및 박물관 문화상품점
  • 지역문화재단과 지방자치단체 관광 부서
  • 관광기념품 제작업체
  • 지역 원단·도자·목공·금속가공 업체
  • 문화상품 기획자와 디자이너

고객이 겪을 수 있는 문제

  • 어떤 유물을 상품 소재로 선택할지 결정하기 어렵습니다.
  • 유물의 역사적 의미를 제품 콘셉트로 옮기기 어렵습니다.
  • 디자인과 업체의 생산 가능 재료·공법이 맞지 않을 수 있습니다.
  • 상품 설명과 홍보 문구의 역사적 사실을 검수해야 합니다.
  • 박물관, 기획자, 디자이너, 제조업체 사이에서 요구사항 전달이 반복됩니다.

따라서 단순한 이미지 생성 서비스보다 다음 형태가 적합합니다.

문화유산 데이터와 지역 제조업체의 생산조건을 연결하여 상품기획서·디자인 브리프·제조 문의서를 만드는 AI MD Copilot

2.2. 데이터 확보 가능성

확보 가능한 데이터

e뮤지엄은 전국 박물관 소장품 통합검색과 Open API 안내를 제공하며 시대·재질·출토지·용도 등의 분류 정보를 확인할 수 있습니다. 게시 자료는 별도 표시가 없는 경우 공공누리 정책에 따라 이용할 수 있다고 안내하지만, 실제 상품 제작에서는 개별 이미지와 문양의 이용조건을 다시 확인해야 합니다.

  • e뮤지엄 전국박물관 소장품 검색
  • e뮤지엄 Open API 이용 안내

확보가 어려운 데이터

  • 업체별 사용 가능 재료
  • 보유 장비와 가공 방식
  • 최소주문수량과 단가
  • 납기와 생산 가능 수량
  • 제품별 불량률과 품질 기준
  • 실제 판매량과 재고
  • 최신 소비자 반응과 시장 트렌드

즉, 유물 데이터보다 공급업체와 시장 데이터의 확보가 더 큰 제한 요소입니다.

2.3. 주요 제한 요소

제한 요소 문제 대응 방향
제조 데이터 부족 추천 결과가 실제 생산조건과 다를 수 있음 업체 인터뷰 또는 생산조건표 확보
이미지·문양 권리 공공 데이터라도 개별 권리가 다를 수 있음 출처·공공누리 유형·상업 이용조건 기록
시장성 검증 부족 생성된 아이디어가 실제로 판매될지 알기 어려움 판매 예측 대신 타깃·가격·차별점 가설 제시
생성 디자인의 유사성 기존 상품이나 문양을 과도하게 모방할 수 있음 디자인 브리프 중심, 최종 디자인은 사람 검토
범위 과다 원료 조달부터 제조·판매까지 연결하기 어려움 한 제품군과 한 기관으로 제한

2.4. 권장 개선안

실제 제조까지 자동화하려 하지 말고 다음 단계에 집중합니다.

  1. 공식 자료에서 유물의 역사적 특징과 상징을 검색합니다.
  2. 형태·문양·재료·색상 등 상품화 가능한 요소를 정리합니다.
  3. 목표 고객과 가격대에 맞는 제품 콘셉트를 제안합니다.
  4. 제조업체 생산조건과 충돌하는 요구사항을 검사합니다.
  5. 역사적으로 부정확하거나 부적절한 표현을 검사합니다.
  6. 업체에 전달할 제품 요구사항 문서를 생성합니다.
  7. 근거가 된 유물 정보와 이용조건을 함께 표시합니다.

2.5. 권장 MVP

대상 기관      지방 국립박물관 1곳
문화유산      대표 유물 10~20점
제품군        문구류 또는 섬유 제품 중 1개
업체 데이터   실제 협력업체 자료 또는 명시적인 예시 생산조건표
핵심 출력      상품기획서 + 디자인 브리프 + 제조 문의 체크리스트
검증 항목      사실성 + 권리 확인 + 생산조건 충족 여부

2.6. 추천 조건

다음 조건 중 하나 이상을 충족하면 추진 가치가 높습니다.

  • 실제 지역업체와 인터뷰할 수 있습니다.
  • 업체에서 생산조건표나 기존 상품 정보를 받을 수 있습니다.
  • 팀원이 상품기획·디자인·제조 분야 취업에 관심이 있습니다.
  • 이미지 생성보다 RAG 기반 기획과 검수에 집중할 수 있습니다.

반대로 실제 업체 데이터 없이 원료 수급·단가·생산 가능성을 보장하려 한다면 교육 주제보다 프로젝트 위험도가 높습니다.

3. 교육 프로그램 관련

3.1. B2B2C 서비스 구조

교육 프로그램은 기존 문화유산 AI 도슨트를 유지하면서 고객과 업무 흐름을 명확하게 만들 수 있습니다.

B2B 고객

  • 박물관 교육 담당자
  • 초·중등 교사
  • 방과후 교육기관과 한국사 학원
  • 에듀테크 기업
  • 지역문화재단

B2C 사용자

  • 초·중등 학생
  • 한국사능력검정시험 학습자
  • 가족 단위 박물관 관람객
  • 한국사 초심자와 일반 관람객
박물관·학교·학원·에듀테크 기업
              ↓ 콘텐츠 제작·검수
       AI 역사교육 콘텐츠 플랫폼
              ↓ 수준별 학습·오답 진단
        학생·학습자·관람객

비용을 지불하거나 도입을 결정하는 주체와 실제 사용자가 구분되므로 B2B2C 서비스로 설명할 수 있습니다.

3.2. 공식 데이터와 제한 사항

한국사능력검정시험은 국사편찬위원회가 주관하며 역사 지식뿐 아니라 연대기 파악, 역사 자료의 분석·해석, 역사적 상황과 쟁점 인식 등을 평가합니다. 따라서 단순 암기형 챗봇보다 자료 해석과 오답 원인 진단으로 발전시키기 좋습니다.

  • 한국사능력검정시험 목적과 출제 유형

다만 공식 시험자료실은 최근 15개 회차의 문제와 정답을 제공하며, 문항에 사용된 사진 등의 저작권은 원저작자에게 있다고 안내합니다.

  • 한국사능력검정시험 공식 시험자료실

따라서 다음 원칙을 적용해야 합니다.

  • 문제지와 정답은 공식 자료를 사용합니다.
  • 사진·지도·삽화는 개별 권리를 확인합니다.
  • 기출문제를 그대로 Fine-tuning 데이터로 넣지 않습니다.
  • 기출문제는 평가, 주제 분류, 오답 진단 기준으로 활용합니다.
  • 사실 해설은 박물관·국사편찬위원회 등 공식 자료로 보강합니다.

  • 근거 없는 문장과 과도한 단순화 표시
  • 담당자 수정·승인 후 학습자에게 제공

4. 길 안내 발전형

4.1. 현재 제안에는 네 프로젝트가 섞여 있습니다

세부 기능 주요 기술 핵심 제한 요소
주차장 탐색·재경로 지도 API, 경로 최적화 실시간 빈자리 데이터
주정차 금지·단속 위험 GIS, 법규·행정 데이터 데이터 시차와 안전 책임
리뷰 분석·장소 추천 NLP, 추천시스템 리뷰 접근권한·공정성·개인정보
그늘·우천 회피 경로 공간분석, 날씨, 3D 건물 정밀 보행 공간정보

각 기능의 데이터와 핵심 기술이 다르므로 하나의 LLM 프로젝트로 묶으면 완성 가능성이 낮습니다.

4.2. 주차장 안내

전국주차장 표준데이터에는 위치, 구획 수, 운영시간, 요금, 결제방법, 장애인 주차구역 등의 정보가 포함됩니다. 그러나 갱신 주기가 반기이므로 이 데이터만으로는 현재 빈자리를 판단할 수 없습니다.

  • 전국주차장정보표준데이터

구현 가능한 기능

  • 목적지 인근 주차장 조회
  • 방문시간 기준 운영 여부 확인
  • 요금·도보거리·주차 규모 비교
  • 장애인 주차구역 보유 여부 확인
  • 여러 후보의 장단점 설명
  • 선택한 주차장을 목적지 또는 경유지로 사용하는 경로 연결

실시간 데이터 없이는 제공하면 안 되는 표현

  • 현재 주차 가능
  • 빈자리 확정
  • 입차 대기시간 보장
  • 현재 단속하지 않음

따라서 서비스는 실시간 주차 가능 여부가 아니라 운영조건 기반 주차 대안 추천으로 정의해야 합니다.

4.3. 주정차 금지·단속 정보

전국 주정차금지구역 표준데이터에는 도로명, 상세 위치, 금지 유형, 요일별 금지·허용 시간이 포함됩니다. 다만 반기 단위로 갱신되며 기관별 데이터 병합에 시차가 있을 수 있습니다.

  • 전국주정차금지구역 표준데이터

일부 지자체의 단속 데이터는 과거 단속 기록이므로 상습 단속지역 분석에는 사용할 수 있지만 현재 단속 차량의 위치를 알려주지는 않습니다.

권장 표현은 다음과 같습니다.

현재 단속 여부가 아니라 법정 주정차 금지구역 및 과거 단속 위험이 높은 구간

LLM이 임의로 주차 가능 여부를 판단하지 않도록 공식 규칙과 데이터 기준일을 함께 표시해야 합니다.

4.4. 경로 API 활용 범위

TMAP은 자동차·화물차·보행자 경로, 경유지 최적화, 교통정보 등의 API와 SDK를 제공합니다. 카카오모빌리티는 자동차 길찾기, 다중 경유지·목적지 API를 제공하며, 네이버 Directions API도 실시간 교통 기반 경로를 제공합니다.

  • TMAP API 공식 안내
  • 카카오모빌리티 길찾기 API
  • NAVER Cloud Directions 15

경로 표시 자체는 외부 API가 해결하므로 프로젝트의 차별화는 다음에 있어야 합니다.

  • 여러 주차장 후보를 어떤 기준으로 평가하는가?
  • 비용·운영시간·도보거리·접근성을 어떻게 조합하는가?
  • 추천 이유를 어떤 데이터에 근거해 설명하는가?
  • 오래되거나 부족한 데이터에 어떻게 경고하는가?

4.5. 리뷰 분석의 제한과 개선안

작성자의 최근 리뷰 이력을 분석해 악성 리뷰를 걸러내는 기능은 플랫폼 데이터 접근, 이용약관, 개인정보, 오판 위험이 큽니다.

MVP에서는 리뷰 작성자를 평가하지 않고 제공받은 리뷰 집합에서 다음만 분석하는 것이 안전합니다.

  • 반복적으로 등장하는 긍정·부정 주제
  • 최근과 과거 리뷰의 변화
  • 음식·가격·대기시간·서비스 등 항목별 의견
  • 리뷰 수가 적을 때 신뢰도 낮음 표시
  • 동일 문구 반복이나 광고성 표현 탐지

이 기능도 주차 안내와 결합하지 않고 별도의 장소 추천 프로젝트로 분리하는 편이 좋습니다.

4.6. 그늘·우천 회피 경로

그늘 경로에는 시간별 태양 위치, 건물 높이, 가로수, 보행로 형상 등이 필요합니다. 비 회피 경로에는 지하상가, 아케이드, 지붕 있는 통로, 실제 출입 가능 여부가 필요합니다.

의미 있는 주제지만 LLM보다 GIS·공간분석·경로 최적화가 핵심이므로 이번 LLM 단위 프로젝트에서는 제외하는 것을 권장합니다.

4.7. 길 안내를 선택할 경우의 권장안

선택안 A — 목적지 기반 주차 대안 의사결정 서비스

대상 지역     한 개 시 또는 한 개 구
목적지        주요 시설 10~20곳
주차장        공식 공공데이터로 확인 가능한 주차장
실시간 여부   제공하지 않음
경로          기존 지도 API 활용
LLM 역할      사용자 조건 해석과 후보별 장단점 설명

선택안 B — 초보운전자 상황 설명 RAG

비보호 좌회전, 회전교차로, 어린이보호구역 등 어려운 도로 상황을 공식 교통법규와 운전 지침에 근거해 설명합니다.

  • 운전 전 경로 학습
  • 운전 후 상황 복습
  • 운전면허와 안전교육
  • 도로표지·교통규칙 질의응답

실시간 운전 중 조작을 전제로 하지 않는 교육·보조 서비스로 제한해야 합니다.

6. 종합 의견

6.1. 강사님 의견을 해석하는 기준

강사님의 의견은 반드시 거대한 상용서비스를 만들라는 의미라기보다 프로젝트를 다음 문장으로 설명할 수 있어야 한다는 뜻에 가깝습니다.

누가 어떤 업무에서 불편을 겪고 있으며, 우리가 만든 AI가 그 업무를 어떻게 개선하는가?

B2B, B2C라는 이름만 붙이는 것으로는 충분하지 않습니다. 고객의 업무 흐름, 데이터, 기능, 성과가 연결되어야 합니다.

6.2. 현재 문화유산 도슨트의 한계

현재 방향은 일반 관람객이 문화유산에 질문하는 B2C 서비스입니다. 구현은 가능하지만 다음 질문에 답하기 어렵습니다.

  • 기존 범용 생성형 AI와 무엇이 다른가?
  • 박물관은 왜 이 서비스를 도입해야 하는가?
  • 담당자의 실제 업무가 얼마나 줄어드는가?
  • 생성된 답변을 누가 검수하고 승인하는가?
  • 서비스의 성능을 어떤 지표로 평가하는가?

6.3. 권장 전환

기존
일반 관람객이 문화유산에 질문하는 AI 도슨트

개선
박물관·교사가 공식 자료 기반 교육 콘텐츠를 제작하고 검수하며,
학생·관람객은 개인 수준에 맞는 해설과 오답 진단을 받는
B2B2C형 AI 역사교육 플랫폼

이 방향은 기존 문화유산 도슨트를 폐기하는 것이 아닙니다. 도슨트 기능은 학습자 화면의 핵심 기능으로 유지하고, 박물관·교사의 콘텐츠 제작과 검수 업무를 추가하는 것입니다.
