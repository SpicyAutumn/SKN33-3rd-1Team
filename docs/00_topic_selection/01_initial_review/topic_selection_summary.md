## 1. 작성 목적

이 문서는 SKN AI 캠프 3차 단위 프로젝트인 **LLM을 연동한 내·외부 문서 기반 질의응답 시스템**의 세부 주제를 선정하기 위해 다음 내용을 보존한다.

- 팀원이 제안한 후보 주제와 제안 배경
- 공식 데이터 확보 가능성에 대한 사전 조사
- RAG, Vector DB, LangChain, LangGraph 등 수업 내용과의 적합성
- 사용자에게 잘못된 답변을 제공했을 때의 위험
- 각 후보의 필수 구현 범위, 한계 및 권장 축소 범위
- 최종 주제 선정 전에 수행할 데이터 검증 계획

현재 평가는 실제 데이터 전체를 수집한 결과가 아니라 **공식 사이트와 공개 API를 기준으로 한 사전 검토**다. 최종 결정은 상위 후보의 데이터를 실제로 수집하고 검색 가능성을 확인한 후 내린다.

### 1.1. 2026-08-26 점심 회의 전 후속 현행화

1차 회의 기록을 수정하거나 덮어쓰지 않고, 팀원 개인이 오전에 제시한 원안이 같은 개인의 회의 전 기획 과정에서 어떻게 구체화되었는지를 다음과 같이 연결해 둔다.

| 후보 | 오전 원안 — 팀원 개인 기획 | 현재 사전 구체화안 — 동일 개인의 후속 기획 | 점심 회의 확인사항 |
|---|---|---|---|
| 역사교육 | 초·중등 교과과정과 한국사능력검정시험을 포괄한 교육 프로그램 | 중학생 한국사 초심자를 위한 박물관·교사용 콘텐츠 제작·검수 및 학습진단 플랫폼 | B2B 핵심 사용자, 대상 박물관, 시대·성취기준 확인 |
| 문화유산 굿즈 | 지역업체와 재료 수급부터 디자인·제조까지 연계 | 유물·고객·상품·제작조건을 바탕으로 기획안과 디자인 방향을 비교하는 의사결정 지원 시스템 | 유물·제품군 범위, 업체 데이터와 이미지 권리 확인 |
| 길 안내 | 주차·단속·리뷰·그늘·교통법규를 포괄한 길 안내 발전형 | 특정 시설 한 곳의 주차장·대중교통·관람·날씨·주변 일정을 통합하는 방문 계획 도우미 | 대상 시설·지역, 교통 API와 실시간 정보 범위 확인 |

오전 원안과 현재 구체화안은 모두 팀원 개인의 기획 기록이며, 위 세 후보의 상태는 `사전 구체화 — 팀 합의 전`이다. 세부 내용과 점심 회의 기록 양식은 [2차 주제 선정 회의록](../02_meeting_records/topic_selection_meeting_2026-08-26.md)을 따른다.

## 3. 2026-08-25 팀 회의 내용

### A팀원 — 자격증 조회

- 국가자격증의 시험 일정, 응시 조건, 시험 과목 등 조회
- 사용자 정보나 목표 직무와 연결한 자격증 추천으로 확장 가능

### B팀원 — 법령 조회 및 해석 챗봇

- 사용자의 질문과 관련된 법령·조문 검색
- 법령 내용을 이해하기 쉬운 표현으로 정리하는 기능 검토

### C팀원 — 사용자 정보 기반 추천 챗봇

#### 자동차 사고 관련

사용자가 사고 상황을 입력하면 다음 결과를 제공하는 방향이다.

1. 사고 설명에서 누락된 사실 확인
2. 확보가 필요한 증거 안내
3. 관련 법령·판례 검색
4. 사고 사실관계 보고서 초안 생성

- 데이터 후보: 국가법령정보 API의 법령·판례, 팀 제작 가상 보험문서
- 목표 사용자: 사고를 처음 겪었거나 과실비율에 이견이 있는 운전자
- 차별점: 과실비율·보험금 예측보다 **증거 공백 분석**에 집중
- 우려 사항: 법률자문처럼 보일 가능성, 정확한 판례 필터링의 어려움

#### 복지 지원금 관련

나이, 소득, 가구 형태, 지역 등을 입력받아 관련 지원금과 복지서비스 후보를 안내하는 방향이다.

- 데이터 후보: 정부·공공기관의 중앙부처 및 지자체 복지서비스 API
- 목표 사용자: 본인에게 관련된 제도를 찾기 어려운 사용자
- 차별점: 여러 기관에 흩어진 지원제도를 사용자 상황 기준으로 묶어 탐색
- 우려 사항: 지자체별 조건과 갱신 시점 차이, 자격요건 오안내의 실생활 영향

### D팀원 — 집 정리 챗봇

- 사용자의 물건, 공간, 성향에 맞는 정리 순서와 방법 추천
- 신뢰도 높은 통합 데이터 확보가 어렵고 개인 선호에 따라 정답이 달라질 수 있다는 우려
- 4차 프로젝트에서 이미지 기반 가구 배치, 분리배출, 쇼핑 품목 추천 등으로 확장 가능성 검토

### E팀원 — 문화유산 및 금융 챗봇

#### 문화유산 챗봇·도슨트

- 국가유산청과 박물관의 공식 데이터를 근거로 유물 설명 제공
- 어린이, 청소년, 성인 등 사용자 유형에 따라 설명 수준 변경
- 외국인 대상 다국어 안내로 확장 가능
- Fine-tuning 적용 여부는 RAG와 프롬프트 기준선을 만든 뒤 비교 검토

#### 금융 챗봇

- 사용자의 조건을 입력받아 관련 금융정보를 설명하거나 후보를 비교
- 공식 금융 데이터는 존재하지만 상품 조건과 금리의 변경이 잦아 지속적인 갱신이 필요하다는 우려

## 4. 공통 평가 기준

모든 점수는 1~5점이며 높을수록 프로젝트 진행에 유리하도록 통일했다.

| 평가 기준 | 확인 내용 |
| :--- | :--- |
| 공식 데이터 | 공공기관 또는 신뢰 가능한 기관의 데이터 확보 가능성 |
| RAG 적합성 | 검색 가능한 설명문과 출처가 충분한지 |
| 개인화 | 사용자 입력에 따라 결과를 의미 있게 달리할 수 있는지 |
| 평가 용이성 | 정답, 근거 문서, 답변 불가 사례를 만들기 쉬운지 |
| 수업 적합성 | RAG·Vector DB·LangChain·LangGraph 학습 내용을 설명하기 좋은지 |
| 안전성 | 오답이 사용자에게 법률·재정·생활상 큰 피해를 줄 가능성이 낮은지 |
| 유지관리 | 데이터 변경이 적고 갱신 부담이 낮은지 |

## 6. 주제별 필수 조건·한계·권장 범위

### 1순위 — 문화유산 도슨트

**필수**

- 대상 기관, 시대, 유물 수와 핵심 사용자 한 그룹을 우선 확정한다.
- 유물명, 시대, 재료, 소장기관, 설명, 출처 URL을 메타데이터로 보존한다.
- 이미지의 이용 조건을 설명문과 별도로 확인한다.
- 근거 문서에 없는 설화나 추측은 답변하지 않도록 한다.

**한계**

- 기관마다 설명문 형식과 상세도가 다를 수 있다.
- 사용자 수준별 말투 조정을 바로 Fine-tuning의 성과로 보기 어렵다.
- 전국 모든 문화유산을 대상으로 하면 데이터 정제와 평가 범위가 급격히 커진다.

**권장**

- 특정 지방박물관 1~2곳의 대표 유물을 대상으로 한다.
- 교과서 또는 한국사 시험에 등장하는 대표 유물부터 시작한다.
- 시대·주제·재료를 조합해 `삼국시대 금속공예`, `고려·조선 도자기`처럼 구성한다.
- 어린이·청소년·성인 설명과 짧은 관람·심층 관람 모드를 프롬프트로 먼저 구현한다.

### 2순위 — 자격증 탐색

**필수**

- 공식 응시 조건과 시험 정보를 출처·기준일과 함께 표시한다.
- 전공, 경력, 목표 직무 등 추천에 실제로 필요한 사용자 입력을 정의한다.
- 시스템이 확인하지 못한 조건은 사용자에게 추가 확인사항으로 안내한다.

**한계**

- 단순 시험 일정 조회에 머물면 LLM과 RAG의 필요성이 약해진다.
- 복잡한 경력 인정 조건은 구조화 데이터만으로 최종 판단하기 어렵다.

**권장**

- `목표 직무와 경험 → 관련 자격증 후보 → 공식 응시조건 체크리스트` 흐름으로 설계한다.
- 응시 가능 여부를 단정하지 않고 공식 확인 경로를 함께 제공한다.

### 3순위 — 복지서비스 추천

**필수**

- 지역과 생애주기 또는 대상 계층을 제한한다.
- 추천 결과에 기준일, 공식 신청 링크, 미확인 조건을 표시한다.
- `수급 가능`이 아니라 `관련성이 높은 후보`로 표현한다.

**한계**

- 자연어로 작성된 소득·가구·자산 조건을 자동 판정하기 어렵다.
- 지자체별 기준과 갱신 시점이 달라 유지관리 부담이 크다.
- 오안내가 실제 신청과 생활 계획에 영향을 줄 수 있다.

**권장**

- 한 지역의 청년, 신혼부부 또는 1인 가구 중 한 그룹으로 한정한다.
- 구조화 조건 필터링 후 RAG로 근거와 신청 방법을 설명한다.

### 4순위 — 법률정보 탐색

**필수**

- 조문, 시행일, 개정일, 판례 출처를 표시한다.
- 비법률자문 안내와 답변 거부 범위를 정의한다.
- 현재 효력이 있는 법령과 과거 법령을 구분한다.

**한계**

- 사실관계에 따라 법 적용 결과가 달라진다.
- 법령 ‘해석’이 법률자문으로 받아들여질 수 있다.
- 판례 검색과 답변 평가에는 도메인 지식이 필요하다.

**권장**

- `법령·판례 정보 내비게이터`로 정의하고 위법 여부나 소송 결과를 판단하지 않는다.
- 관련 조문, 개정 정보, 판례의 핵심 쟁점과 확인사항까지만 제공한다.

### 5순위 — 집 정리 도우미

**필수**

- 정리 방법에 사용할 팀 규칙과 평가 기준을 명시한다.
- 분리배출 정보는 사용자의 지역별 공식 자료와 연결한다.
- 사용자 성향, 공간, 물품 목록을 구분해 입력받는다.

**한계**

- 통합된 공신력 있는 정리 지식이 부족하다.
- 개인 선호에 따라 같은 입력에도 여러 답이 가능하다.
- 일반 LLM 프롬프트 서비스가 되어 문서 기반 RAG 특성이 약해질 수 있다.

**권장**

- 물품 목록 기반 정리 순서와 처분 방법 안내로 좁힌다.
- 공간 이미지와 가구 배치는 후속 프로젝트의 확장 범위로 둔다.

### 6순위 — 자동차 사고 정리

**필수**

- 사고 사실, 누락 사실, 필요한 증거를 구분한다.
- 공식 자료의 이용 조건과 가상 보험문서 여부를 명시한다.
- 과실비율, 보험금, 법적 책임을 예측하지 않는 안전장치를 둔다.

**한계**

- 불완전한 사고 설명만으로 사실관계를 확정하기 어렵다.
- 도로 구조, 차량 방향, 신호 등 판례 검색 조건이 복잡하다.
- 답변이 법률 또는 보험 자문으로 받아들여질 위험이 크다.

**권장**

- `사고 사실·증거 정리 도우미`로 범위를 축소한다.
- 필요한 증거, 추가 질문, 공식 참고자료, 상담 시 확인할 항목만 제공한다.

### 7순위 — 금융정보 챗봇

**필수**

- 공식 출처와 조회 기준일을 모든 결과에 표시한다.
- 최신 API 데이터와 벡터DB에 저장한 설명문을 분리한다.
- 투자권유, 수익률 예측, 대출 승인 가능성 단정을 차단한다.

**한계**

- 금리와 상품 조건이 자주 변경된다.
- 개인화 추천의 오답이 사용자의 재정 판단에 직접 영향을 준다.
- ‘금융’ 전체를 대상으로 하면 데이터와 기능 범위가 지나치게 넓다.

**권장**

- 금융용어, 상품설명서, 공시, 서민금융 중 하나만 선택한다.
- 조건 설명과 정보 비교까지만 제공하고 최종 선택은 사용자에게 남긴다.

## 7. 2026-08-25 당시 잠정 결론

> 아래 내용은 1차 회의 당시의 잠정 결론으로 보존한다. 2026-08-26 사전 구체화안이나 점심 회의 결과를 의미하지 않는다.

1. **문화유산 도슨트**, **자격증 탐색**, **범위를 제한한 복지서비스 추천**을 우선 데이터 검증 후보로 둔다.
2. 최종 주제는 아직 확정하지 않는다.
3. 상위 후보별 공식 데이터 30~100건을 실제로 수집해 설명문, 메타데이터, 라이선스와 검색 가능성을 확인한다.
4. 법률, 자동차 사고, 금융 주제는 정보 검색과 확인사항 안내로 범위를 축소하지 않으면 교육 프로젝트에서 안전성과 평가 부담이 크다.
5. Fine-tuning은 주제 선정 근거로 먼저 확정하지 않는다. 기본 RAG와 프롬프트로 해결되지 않는 일관된 표현·분류 문제가 확인될 때 비교 실험한다.
