# 테스트 계획 및 결과 보고서

> 계획 단계에서는 목표와 케이스를 작성하고, 구현 후 같은 문서에 실제 결과와 분석을 추가합니다.

## 1. 테스트 목적

- 문서 수집부터 답변까지의 기능이 정상 동작하는지 확인한다.
- 검색 실패와 생성 실패를 분리해 원인을 분석한다.
- 문서 밖 질문에 추측하지 않는지 확인한다.
- 개선 기법이 동일 평가 세트에서 기본 RAG보다 실제로 나은지 비교한다.

## 4. 평가 기준

### 검색 평가

- `Hit@k`: 기대 근거 문서가 상위 k개 검색 결과에 하나 이상 포함된 비율
- 검색 실패 사례: 기대 출처가 검색되지 않은 질문 목록

### 답변 수동 평가표

| 점수 | 답변 정확성/근거 일치 | 출처 정확성 |
| :---: | :--- | :--- |
| 2 | 핵심 내용이 맞고 문서 근거와 일치 | 출처가 답변을 직접 뒷받침 |
| 1 | 일부 맞지만 누락·과장이 있음 | 관련은 있으나 직접 근거가 약함 |
| 0 | 틀리거나 근거 밖 내용을 생성 | 출처가 없거나 잘못됨 |

두 명이 독립 평가하는 경우 불일치 항목을 함께 검토하고 최종 판단 근거를 기록합니다.

### 답변 불가 평가

- 답변 불가 질문을 올바르게 거절한 비율
- 답변 가능한 질문을 잘못 거절한 비율
- 근거 없이 답한 질문 목록

### 비기능 평가

- 평균/최대 응답 시간
- 질문당 입력·출력 토큰 또는 비용
- API 오류와 재시도 횟수
