# 질의응답 1 — 왜 문화유산 전체가 아니라 범위를 먼저 좁혀야 하는가?

## 1. 질의

> **“문화유산 전체”를 대상으로 하지 말고 대상 기관·시대·유물 범위와 핵심 사용자 한 그룹을 우선 확정하는 것이 중요하다는 것에 대해서 자세하게 설명해 줘.**

## 2. 답변

### 핵심 답변

핵심은 **범위를 좁히는 것이 기능을 포기하는 것이 아니라, RAG가 제대로 작동하는지 검증할 수 있는 실험 범위를 만드는 것**입니다.

문화유산 전체를 대상으로 시작하면 겉으로는 풍부한 서비스처럼 보이지만, 실제 프로젝트에서는 데이터 수집·전처리·검색·답변 생성·평가의 기준이 모두 흔들릴 가능성이 큽니다. 반대로 대상 기관, 시대, 유물 범위, 핵심 사용자를 먼저 정하면 다음 질문에 명확하게 답할 수 있습니다.

- 어떤 자료를 수집해야 하는가?
- 어떤 메타데이터를 저장해야 하는가?
- 사용자의 질문에서 무엇을 검색해야 하는가?
- 답변에 반드시 포함해야 할 근거는 무엇인가?
- 시스템이 잘 작동했다고 판단할 평가 기준은 무엇인가?

즉, 범위 설정은 단순한 기획 단계가 아니라 **데이터 설계, 검색 설계, 프롬프트 설계, 테스트 설계를 연결하는 기준점**입니다.

---

### 2.1. “문화유산 전체”가 프로젝트 범위로 너무 넓은 이유

#### ① 데이터의 종류와 구조가 지나치게 다릅니다

문화유산에는 다음과 같이 성격이 전혀 다른 대상이 포함됩니다.

- 박물관 유물
- 궁궐·사찰·성곽 등의 건축문화유산
- 무형유산과 전통 기술
- 기록유산
- 자연유산
- 지역·인물·사건과 연결된 역사 정보

예를 들어 박물관 유물은 `명칭`, `시대`, `재료`, `크기`, `소장 기관`, `설명`처럼 비교적 구조화하기 쉽습니다. 반면 건축문화유산은 `위치`, `건립 시기`, `중수 이력`, `공간 구성`이 중요하고, 무형유산은 `보유자`, `전승 방식`, `행사`, `기술 과정`이 중요합니다.

이 모든 자료를 한 번에 다루면 공통 스키마를 만들기 어렵고, 문서 분할 기준과 검색 필터도 복잡해집니다. 결국 수집량은 많아지지만 검색 정확도는 낮아질 수 있습니다.

#### ② 같은 단어가 여러 의미로 사용될 수 있습니다

문화유산 질문에는 시대, 인물, 지역, 유물명처럼 서로 겹치는 표현이 많습니다.

예를 들어 사용자가 “백제 금동대향로를 설명해 줘”라고 질문했을 때 필요한 것은 특정 유물의 공식 설명입니다. 그러나 전체 문화유산 문서가 섞여 있으면 백제 시대 일반 설명, 부여 지역 관광 정보, 향로와 관련된 다른 유물, 복원 행사 등의 자료가 함께 검색될 수 있습니다.

범위를 박물관 유물로 제한하면 다음과 같은 메타데이터 필터를 사용할 수 있습니다.

```text
기관 = 특정 박물관
시대 = 백제
유형 = 향로
재료 = 금속
유물 ID = 공식 소장품 식별자
```

이렇게 하면 벡터 검색 결과를 구조화된 조건으로 다시 좁힐 수 있어 검색 품질을 설명하고 개선하기 쉬워집니다.

#### ③ 답변 형식을 통일하기 어렵습니다

박물관 유물에 대한 답변은 다음과 같은 공통 형식으로 설계할 수 있습니다.

1. 한 문장 핵심 설명
2. 시대와 제작 배경
3. 꼭 봐야 할 특징
4. 역사적 의미
5. 공식 출처

하지만 건축물, 무형유산, 자연유산까지 포함하면 각각 필요한 설명 항목이 달라집니다. 프로젝트 초기에 답변 형식이 계속 달라지면 프롬프트와 평가 기준이 불안정해집니다.

#### ④ 환각 여부를 평가하기 어려워집니다

RAG 프로젝트에서 중요한 것은 답변이 자연스러운가보다 **검색된 근거에 맞게 답했는가**입니다.

범위가 너무 넓으면 평가자가 모든 분야의 사실을 확인하기 어렵고, 정답 문서도 일관되게 구성하기 어렵습니다. 반면 특정 박물관과 특정 유물 집합을 대상으로 하면 공식 설명과 답변을 직접 비교할 수 있습니다.

평가 항목도 다음과 같이 구체화할 수 있습니다.

| 평가 항목 | 확인 내용 |
|---|---|
| 검색 적합성 | 질문과 관련된 유물 문서가 검색되었는가? |
| 사실 정확성 | 공식 자료에 없는 내용을 사실처럼 말하지 않았는가? |
| 출처 일치 | 답변의 주장과 제시한 출처가 연결되는가? |
| 답변 완전성 | 사용자가 요청한 핵심 내용을 빠뜨리지 않았는가? |
| 수준 적합성 | 같은 사실을 대상 사용자에게 맞는 표현으로 설명했는가? |
| 답변 보류 | 근거가 부족할 때 모른다고 안내했는가? |

#### ⑤ 교육 프로젝트의 핵심 기술을 보여주기 어려워집니다

이번 프로젝트의 목적은 문화유산 데이터를 최대한 많이 모으는 것이 아니라, 수업에서 배운 내용을 사용해 다음 흐름을 구현하고 설명하는 것입니다.

```text
공식 문서 수집
  → 전처리 및 청크 분할
  → 임베딩 및 Vector DB 저장
  → 질문에 맞는 문서 검색
  → 검색 근거를 사용한 LLM 답변
  → 출처 표시 및 환각 평가
```

범위가 지나치게 크면 팀의 시간이 데이터 수집과 예외 처리에 집중되고, 정작 RAG 검색 품질·프롬프트·평가 실험이 약해질 수 있습니다.

### 2.2. 먼저 고정해야 하는 네 가지 범위

| 범위 축 | 결정해야 하는 질문 | 결정 예시 | 결정 효과 |
|---|---|---|---|
| 대상 기관 | 어느 기관의 공식 자료를 사용할 것인가? | 지방 국립박물관 1곳 | 출처와 수집 경로가 선명해짐 |
| 시대·주제 | 어떤 역사 범위를 다룰 것인가? | 삼국시대, 고려→조선 도자 변화 | 검색 대상과 질문 유형이 정리됨 |
| 유물 범위 | 어떤 유물 집합을 수집할 것인가? | 대표 유물, 교과서 연계 유물 | 데이터셋 선정 기준을 만들 수 있음 |
| 핵심 사용자 | 첫 번째 버전은 누구를 위한 것인가? | 일반 관람객 | 어휘, 길이, 답변 구조를 고정할 수 있음 |

네 가지를 한 번에 완벽하게 결정할 필요는 없습니다. 다만 첫 데이터 수집 전에 **임시 범위라도 문장으로 고정**해야 팀원들이 같은 대상을 보고 작업할 수 있습니다.

예시는 다음과 같습니다.

> **지방 국립박물관 한 곳의 대표 유물을 대상으로, 일반 관람객이 1분 안에 이해할 수 있는 핵심 해설과 공식 출처를 제공하는 RAG 기반 AI 도슨트를 개발한다.**

이 문장은 최종 주제가 아니라, 데이터 확보 가능성과 RAG 품질을 검증하기 위한 MVP 범위 예시입니다.

---

### 2.3. 핵심 사용자 한 그룹을 먼저 정해야 하는 이유

어린이, 초등학생, 중학생, 고등학생, 성인, 한국사 초심자, 역사 관심층을 처음부터 모두 지원하면 답변의 어휘와 길이뿐 아니라 배경지식, 질문 방식, 설명 목표까지 달라집니다.

예를 들어 같은 금관을 설명하더라도 요구되는 답변은 다릅니다.

| 사용자 | 설명의 중심 |
|---|---|
| 어린이 | 눈에 보이는 특징, 쉬운 비유, 짧은 문장 |
| 청소년 | 교과 개념, 시대적 맥락, 핵심 용어 |
| 일반 관람객 | 짧은 핵심 설명, 관람 포인트, 대표 의미 |
| 역사 관심층 | 제작기법, 다른 유물과의 비교, 해석의 맥락 |

여러 사용자를 동시에 구현하면 답변이 달라진 이유가 RAG 검색 때문인지, 프롬프트 때문인지, Fine-tuning 때문인지 구분하기 어려워집니다.

따라서 첫 번째 실험에서는 다음처럼 분리하는 것이 좋습니다.

- **검색·근거 계층:** 모든 사용자에게 동일한 공식 자료와 핵심 사실 사용
- **표현 계층:** 사용자 수준에 따라 어휘, 길이, 예시, 질문만 조정

이 구조의 장점은 사용자 유형을 나중에 추가해도 Vector DB를 처음부터 다시 만들 필요가 적다는 점입니다.

---

### 2.4. 범위를 좁히면 각 기술을 더 명확하게 검증할 수 있습니다

#### RAG

- 질문과 관련된 유물 문서가 검색되는지 확인할 수 있습니다.
- 같은 질문에 대해 검색 방식별 결과를 비교할 수 있습니다.
- 공식 자료가 없을 때 답변을 보류하도록 설계할 수 있습니다.

#### Vector DB

- 시대, 기관, 재료, 유형 등의 메타데이터 필터를 실험할 수 있습니다.
- 청크 크기와 임베딩 모델에 따른 검색 차이를 비교할 수 있습니다.
- Dense 검색과 키워드 검색의 결합 필요성을 확인할 수 있습니다.

#### LangChain·LangGraph

- 수집 → 검색 → 답변 → 검증 흐름을 단계별로 구성할 수 있습니다.
- 모든 질문에 복잡한 에이전트를 적용하지 않고, 근거 부족이나 재검색이 필요한 경우에만 분기할 수 있습니다.
- 교육에서 배운 체인과 그래프 개념을 실제 처리 흐름과 연결할 수 있습니다.

#### 환각 방지

- 답변에 사용할 수 있는 근거 문서의 범위를 명확히 할 수 있습니다.
- 출처가 없는 문장을 검사하기 쉬워집니다.
- “자료에서 확인되지 않습니다”와 같은 답변 보류 규칙을 테스트할 수 있습니다.

#### Fine-tuning

- Fine-tuning이 정말 필요한지 비교 실험할 수 있습니다.
- RAG와 프롬프트만 사용한 기준 모델을 먼저 확보할 수 있습니다.
- 필요하다면 사실 암기가 아니라 설명 수준과 답변 형식의 일관성을 학습 목표로 설정할 수 있습니다.

> [!CAUTION]
> Fine-tuning을 먼저 적용하면 검색 문제와 표현 문제를 구분하기 어려워질 수 있습니다. 우선 RAG와 Prompt Engineering으로 기준 성능을 확인한 뒤, 반복적으로 해결되지 않는 문제가 있을 때 적용 여부를 결정하는 것이 안전합니다.

---

### 2.5. 범위를 좁힌 뒤 확장하는 순서

```text
1단계: 지방 국립박물관 1곳 + 대표 유물 + 일반 관람객
  ↓
2단계: 같은 데이터에서 1분 핵심 / 더 깊이 보기 제공
  ↓
3단계: 어린이 / 청소년 설명 수준 추가
  ↓
4단계: 역사적으로 연결되는 지역 박물관 또는 유물 비교
  ↓
5단계: 필요성이 검증된 경우 GraphRAG·Fine-tuning 확장
```

이 순서에서는 매 단계마다 이전 버전과 성능을 비교할 수 있습니다. 따라서 기능을 많이 구현했다는 사실보다 **어떤 확장이 어떤 문제를 해결했는지** 발표하기 쉬워집니다.

---

### 2.6. 질의응답 1의 결론

> **문화유산 전체를 처음부터 다루지 않는 이유는 데이터가 부족해서가 아니라, 검색과 답변의 품질을 검증할 수 있는 기준을 확보하기 위해서입니다.**

첫 번째 버전은 다음 조건을 만족하면 충분합니다.

- [ ] 공식 자료의 출처가 명확하다.
- [ ] 수집 대상과 제외 대상이 구분된다.
- [ ] 질문에 맞는 유물을 검색할 수 있다.
- [ ] 답변이 검색 근거 안에서 생성된다.
- [ ] 핵심 사용자에게 적절한 길이와 표현을 제공한다.
- [ ] 근거가 부족하면 답변을 보류한다.
- [ ] 평가 질문으로 개선 전후를 비교할 수 있다.

이 기준을 충족한 뒤 기관, 시대, 사용자, 관람 모드를 확장하는 것이 프로젝트 완성도와 교육적 의미를 모두 확보하는 방법입니다.

# 질의응답 2 — 박물관·유물 분류·사용자 수준·관람 깊이 설계

## 1. 질의

> 1. 충분히 이해했어. 일반 관람객을 대상으로 하는 경우 박물관 유물이 보다 용이할 것으로 판단돼.
> 2. 국중박은 현재 국내뿐만 아니라 해외에서도 인기가 있다 보니, 홈페이지에서 충실하게 확인이 가능할 것으로 예상하고 있어. 각 지방에 위치한 박물관을 대상으로 하는 것이 보다 특색 있고 유의미하지 않을까 싶어.
> 3. 시대별 분류를 생각하고 있었는데, 단순히 시대/주제/재료로 구분하기보다 이를 조화롭게 섞을 수 있는 방안이 있을까?
>
>    예) 삼국시대 금관 / 고려-조선 청자 등
>
> 4. 교과서/한국사시험에 등장하는 유물로 정하면 보다 용이할 것 같아.
> 5. 초중고 / 성인(국중박/한국사 관심 유/무) 정도로 정리하는 것이 어떨까 싶어.
> 6. 5번과 연계, 박물관을 짧게 관람하는 유형과 깊이 있게 관람하는 유형으로 구분하는 것은 어떨까 싶어.
> 7. 5~6번과 연계하여 확장하는 형태로 이해하면 될 것 같아.
> 8. 사용자 분류를 선택하는 것이 용이할 수는 있지만 접근성은 떨어질 수도 있지 않을까 우려되는 부분이 있어. 다만, 제시해 준 일반 텍스트 수준(어린이/청소년 등) 정도로만 선택하게 하는 것은 괜찮을 것 같아.
> 9. Fine-tuning에 대한 부분은 지금 당장 방향을 제시하기보다는 보다 깊이 있게 고민이 필요할 것 같아.
>
> 이후 단계의 의견은 현재 단계에서는 불필요할 것 같아서, 우선 9번까지 단계에 대한 간단한 의견을 제시해봤어.

## 2. 답변

### 핵심 답변

제시한 1~9번의 방향은 전반적으로 타당합니다. 가장 중요한 정리는 **유물 분류, 사용자 수준, 관람 깊이를 서로 다른 축으로 분리하는 것**입니다.

- 유물 분류는 **무엇을 검색할 것인가**를 결정합니다.
- 사용자 수준은 **어떤 표현으로 설명할 것인가**를 결정합니다.
- 관람 깊이는 **얼마나 길고 깊게 설명할 것인가**를 결정합니다.

이 세 가지를 하나의 사용자 유형으로 합치면 경우의 수가 지나치게 많아집니다. 반대로 독립된 축으로 관리하면 기본 기능은 단순하게 유지하면서 조합을 통해 다양한 경험을 제공할 수 있습니다.

---

### 2.1. 일반 관람객과 박물관 유물의 조합

일반 관람객을 핵심 사용자로 정하고 박물관 유물을 대상으로 시작하는 방향은 적절합니다.

박물관 유물은 일반적으로 다음 정보를 확보하기 쉽습니다.

- 공식 유물명과 소장품 번호
- 시대 또는 제작 시기
- 재료와 제작기법
- 크기와 형태
- 발굴지·출토지 또는 관련 지역
- 전시 해설과 소장품 설명
- 공식 상세 페이지

또한 관람객이 실제 전시장에서 궁금해할 질문을 만들기 쉽습니다.

```text
이 유물은 무엇에 사용했나요?
왜 이 부분을 꼭 봐야 하나요?
어느 시대에 만들었나요?
비슷한 유물과 무엇이 다른가요?
교과서에서 본 유물과 같은 것인가요?
```

따라서 데이터, 사용자 질문, RAG 답변, 평가 시나리오를 하나의 관람 경험으로 연결하기 좋습니다.

---

### 2.2. 국립중앙박물관보다 지방 박물관을 우선 검토하는 방안

지방 박물관을 중심으로 하는 방향은 프로젝트의 차별성을 만들 수 있습니다. 국립중앙박물관은 자료가 풍부하고 대표성이 높지만, 지방 박물관은 해당 지역의 역사와 출토 유물을 하나의 이야기로 연결하기 좋습니다.

#### 지방 박물관 중심 주제의 장점

- 지역의 역사적 맥락을 살릴 수 있습니다.
- 특정 시대나 정치체와 연결되는 대표 유물이 분명합니다.
- 대형 박물관 전체를 다루는 것보다 데이터 범위를 통제하기 쉽습니다.
- 잘 알려지지 않은 유물을 소개한다는 프로젝트의 의미가 생깁니다.
- 지역 간 유물 비교로 확장할 수 있습니다.

#### 초기 범위에서 주의할 점

여러 지방 박물관을 동시에 선택하면 다시 범위가 넓어질 수 있습니다. 따라서 초기에는 다음 순서를 권장합니다.

1. 지방 국립박물관 한 곳을 기준 기관으로 선정합니다.
2. 대표 전시 또는 대표 유물 집합 한 개를 정합니다.
3. 공식 상세 정보의 수량과 품질을 확인합니다.
4. 데이터와 평가가 안정되면 역사적으로 연결되는 박물관 한 곳을 비교 대상으로 추가합니다.

예를 들어 경주, 공주, 부여, 김해처럼 특정 고대 국가나 지역사와 연결되는 기관을 후보로 두고, 실제 공식 자료의 접근성과 상세도를 먼저 비교할 수 있습니다. 이 문서에서는 특정 기관을 최종 선정하지 않습니다.

---

### 2.3. 시대·주제·재료를 조화롭게 섞는 방법

시대, 주제, 재료를 하나의 고정 분류 체계로 합치기보다 다음 두 계층으로 나누는 것이 좋습니다.

#### 내부 데이터 계층: 속성을 분리하여 저장

```text
기관 / 지역 / 시대 / 정치체 / 유물 유형 / 재료 / 제작기법 / 교육 태그 / 대표성
```

각 속성을 별도 메타데이터로 저장하면 검색 필터와 비교 조건을 유연하게 만들 수 있습니다.

#### 사용자 큐레이션 계층: 여러 속성을 이야기로 조합

| 큐레이션 예시 | 조합되는 내부 속성 | 설명 방향 |
|---|---|---|
| 삼국시대 금관 | 시대 + 정치체 + 유형 + 재료 + 지역 | 나라별 금관 특징과 권력 표현 비교 |
| 고려청자에서 조선 분청사기·백자로 | 시대 변화 + 재료 + 제작기법 + 미감 | 시대 변화에 따른 도자의 기능과 표현 비교 |
| 교과서에서 본 대표 유물 | 교육 태그 + 시대 + 대표성 + 기관 | 학습한 유물을 실제 전시와 연결 |
| 지역 박물관에서 만나는 고대 왕국 | 기관 + 지역 + 정치체 + 대표 유물 | 지역사와 출토 유물의 관계 설명 |

> [!TIP]
> “고려-조선 청자”보다는 **“고려청자에서 조선 분청사기·백자로”**처럼 변화의 방향이 드러나는 이름이 더 정확합니다. 조선시대 도자의 대표 유형까지 포함해 시대 전환을 설명할 수 있기 때문입니다.

이 구조를 사용하면 데이터는 중복 저장하지 않으면서도 다양한 전시 주제를 만들 수 있습니다.

---

### 2.4. 교과서·한국사 시험에 등장하는 유물의 활용

교과서나 한국사 학습에 등장하는 대표 유물을 기준으로 시작하는 것은 사용자 질문과 평가 문제를 만들기 쉽다는 장점이 있습니다.

#### 장점

- 사용자에게 익숙한 유물이 많습니다.
- 예상 질문을 만들기 쉽습니다.
- 시대와 핵심 개념을 연결하기 좋습니다.
- 일반 관람객과 학생 사용자 모두에게 활용할 수 있습니다.
- 평가용 정답과 핵심 키워드를 구성하기 쉽습니다.

#### 주의사항

- 특정 시험 출제 여부만으로 유물의 중요성을 판단하지 않습니다.
- 교과서·시험 자료의 문장을 그대로 학습 데이터로 사용하지 않습니다.
- 어떤 교과서와 교육과정을 기준으로 했는지 기록해야 합니다.
- 최종 사실 설명은 박물관과 공공기관의 공식 자료로 검증해야 합니다.

따라서 `교과서 등장 유물`을 데이터의 유일한 범위로 고정하기보다, 다음과 같은 **교육 태그**로 활용하는 것이 유연합니다.

```text
education_tag = 교과서 연계 / 한국사 핵심 / 일반 교양 / 심화 탐구
```

### 2.5. 초·중·고·성인과 관심도 분류

초등학생, 중학생, 고등학생, 성인과 같이 세밀하게 구분하면 설명을 정확하게 조절할 수 있지만, 초기 버전에서는 조합 수가 빠르게 증가합니다.

예를 들어 다음 조건을 모두 조합하면 경우의 수가 많아집니다.

```text
학교급 4종 × 관심도 2종 × 관람 깊이 2종 = 최소 16가지
```

여기에 질문 유형과 큐레이션까지 추가되면 테스트해야 할 답변이 지나치게 많아집니다.

초기에는 다음 세 수준으로 단순화하는 방안을 권장합니다.

| 화면 표시 | 설명 기준 | 비고 |
|---|---|---|
| 어린이 | 쉬운 단어, 짧은 문장, 관찰 중심 | 세부 학교급은 후속 검토 |
| 청소년 | 교과 개념, 시대 맥락, 핵심 용어 | 중·고등 수준을 우선 통합 |
| 일반 | 관람 포인트, 배경 설명, 공식 출처 | 기본 선택값으로 사용 |

성인의 역사 관심 유무는 별도의 프로필로 받기보다 `1분 핵심`과 `더 깊이 보기`의 차이로 반영하는 편이 자연스럽습니다.

---

### 2.6. 짧게 관람하기와 깊이 있게 관람하기

관람 깊이를 분리하는 방향은 매우 적절합니다. 연령이나 관심도보다 사용자가 지금 사용할 수 있는 시간과 원하는 정보량을 직접 반영하기 때문입니다.

#### 1분 핵심

- 한 문장 설명
- 꼭 봐야 할 특징 2~3개
- 유물의 대표 의미
- 공식 출처

#### 더 깊이 보기

- 역사적 배경
- 제작기법과 재료
- 다른 유물과의 비교
- 관련 시대·인물·지역
- 추가 질문 또는 관찰 포인트
- 공식 출처

두 모드는 서로 다른 답변 시스템일 필요가 없습니다. 같은 검색 근거를 사용하고, 답변 구성과 길이만 다르게 하면 됩니다.

```text
동일한 검색 근거
  ├─ 1분 핵심: 핵심 사실과 관찰 포인트만 요약
  └─ 더 깊이 보기: 배경·기법·비교 정보를 추가
```

---

### 2.7. 사용자 수준과 관람 깊이를 단계적으로 확장하는 방식

사용자 수준과 관람 깊이는 다음 순서로 확장하는 것이 안전합니다.

| 단계 | 사용자 | 관람 깊이 | 검증 목적 |
|---|---|---|---|
| 1단계 | 일반 관람객 | 1분 핵심 | 기본 RAG와 출처 품질 검증 |
| 2단계 | 일반 관람객 | 더 깊이 보기 | 같은 근거에서 답변 확장 가능성 검증 |
| 3단계 | 어린이·청소년 | 1분 핵심 | 표현 수준 조정 검증 |
| 4단계 | 어린이·청소년 | 더 깊이 보기 | 교육형 질문과 비교 설명 확장 |

이 방식은 한 번에 모든 조합을 구현하지 않으면서도 최종 서비스의 확장 구조를 보여줄 수 있습니다.

---

### 2.8. 사용자 선택과 접근성 문제

사용자 분류를 첫 화면에서 반드시 선택하게 하면 다음 문제가 생길 수 있습니다.

- 사용자가 어떤 항목을 선택해야 할지 고민하게 됩니다.
- 질문하기 전에 추가 단계가 생깁니다.
- “나는 초심자인가, 일반인가?”처럼 구분 자체가 부담이 될 수 있습니다.
- 모바일 환경에서 선택 항목이 많아질 수 있습니다.

따라서 선택을 필수로 만들기보다 다음과 같이 설계하는 것이 좋습니다.

1. 기본값은 `일반 · 1분 핵심`으로 설정합니다.
2. 사용자는 선택 없이 바로 질문할 수 있습니다.
3. 필요한 경우에만 `어린이 / 청소년 / 일반`을 바꿉니다.
4. 답변 아래에 `더 쉽게` 또는 `더 깊이 보기`를 제공합니다.

예시 화면 흐름은 다음과 같습니다.

```text
[질문 입력]
설명 수준: 일반 ▼    관람 깊이: 1분 핵심 ▼

AI 답변
  - 한 문장 설명
  - 꼭 볼 특징
  - 공식 출처

[더 쉽게] [더 깊이 보기]
```

이 구조에서는 초심자도 설정 없이 사용할 수 있고, 원하는 사용자는 설명 수준을 조절할 수 있습니다.

---

### 2.9. Fine-tuning은 지금 확정하지 않는 것이 적절합니다

Fine-tuning은 프로젝트에서 사용할 수 있는 기술이지만, 반드시 사용해야 하는 기능은 아닙니다. 먼저 다음 기준 모델을 만들어야 필요성을 판단할 수 있습니다.

```text
기본 LLM
  → Prompt 적용
  → RAG + Prompt 적용
  → 필요할 경우 Fine-tuning 비교
```

먼저 RAG와 Prompt Engineering으로 다음 항목을 확인합니다.

- 공식 자료에 기반해 답변하는가?
- 출처를 정확하게 표시하는가?
- 어린이·청소년·일반 설명 차이가 충분한가?
- 답변 형식이 반복적으로 흔들리는가?
- 근거 부족 시 답변 보류 규칙을 지키는가?

위 문제 중 프롬프트만으로 해결되지 않는 부분이 반복적으로 확인될 때 Fine-tuning을 검토할 수 있습니다.

Fine-tuning을 적용한다면 사실 지식을 암기시키는 것보다 다음 목표가 적절합니다.

- 설명 수준별 어휘와 문장 구조의 일관성
- 도슨트 답변 형식의 일관성
- 공식 출처를 우선하는 답변 태도
- 근거가 부족할 때 추측하지 않는 응답 습관

> [!NOTE]
> 현재 단계의 결론은 “Fine-tuning을 사용하지 않는다”가 아니라 **“RAG와 Prompt 기준 성능을 확인하기 전에는 적용 여부를 확정하지 않는다”**입니다.

---

### 2.10. 질의응답 2의 결론

1~9번의 의견을 종합하면 다음 구조가 가장 단순하면서도 확장성이 있습니다.

```text
유물 검색 범위
  = 기관 + 지역 + 시대 + 유형 + 재료 + 교육 태그

사용자 표현 수준
  = 어린이 / 청소년 / 일반

관람 깊이
  = 1분 핵심 / 더 깊이 보기

응답 원칙
  = 동일한 공식 근거 + 수준과 깊이에 따른 표현 조정
```

핵심 사용자 한 그룹을 먼저 정하되, 다른 사용자 유형을 버리는 것이 아닙니다. **일반 관람객을 기준으로 RAG 품질을 먼저 검증하고, 동일한 데이터와 검색 구조 위에 설명 수준과 관람 깊이를 단계적으로 추가하는 방식**입니다.

| 교과서 속 대표 유물 | 교육 태그 + 시대 + 대표성 | 익숙한 질문과 평가 문제 구성에 유리함 | 교육과정 기준과 공식 근거 연결 |
| 지역 박물관의 고대 왕국 | 기관 + 지역 + 정치체 + 대표 유물 | 지방 박물관의 특색을 살릴 수 있음 | 비교 범위를 한 곳부터 시작할지 여부 |

## 최종 요약

> **작게 시작하되 확장 구조를 먼저 설계합니다.**  
> 첫 번째 목표는 문화유산 전체를 설명하는 AI가 아니라, 제한된 공식 박물관 자료에서 질문과 관련된 유물을 정확히 찾고, 일반 관람객에게 이해하기 쉬운 답변과 출처를 제공하는 RAG 시스템을 완성하는 것입니다.

이를 검증한 뒤 같은 데이터와 검색 구조를 유지하면서 다음 기능을 순서대로 확장할 수 있습니다.

1. `1분 핵심 → 더 깊이 보기`
2. `일반 → 어린이·청소년`
3. `박물관 1곳 → 연결된 기관 비교`
4. `단일 유물 설명 → 시대·지역·재료 관계 탐색`
5. `Prompt + RAG → 필요성이 확인된 Fine-tuning`

이 접근은 프로젝트 일정과 난이도를 통제하면서도 RAG, Vector DB, Prompt Engineering, LangChain·LangGraph, 환각 방지, Fine-tuning 비교라는 교육 목표를 단계적으로 보여줄 수 있습니다.
